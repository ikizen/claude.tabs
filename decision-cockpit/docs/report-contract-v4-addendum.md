# АДДЕНДУМ К ТЕХСПЕКЕ ОТЧЁТА · v4

Добавляет одну секцию к контракту (v1–v3 не меняются). Как и раньше — опциональная: нет секции, нет данных — вкладка «ABC-анализ» скрыта или показывает только то, что есть.

## `abcproducts` — сырые данные для ABC-анализа по товарам

```markdown
<!-- abcproducts:start -->
## ABC ПО ТОВАРАМ
| Модель | Категория | Количество | Выручка | Маржа |
|---|---|---|---|---|
| Колготки Игла арт.К60 мал/дев. | 7 - БЕЛЬЕ/ЧУЛОЧНО-НОСОЧНЫЕ | 14435 | 45000000 | 0.229 |
<!-- abcproducts:end -->
```

**Важно: класс (A/B/C) и накопленную долю сюда добавлять не нужно** — в отличие от `procurement.Класс_ABC`, эта классификация не требует экспертного решения, а считается детерминированно по правилу Парето (сортировка по выручке по убыванию, накопленная доля: первые 80% — класс A, следующие 15% — B, последние 5% — C). Сайт считает её сам в браузере из сырых чисел. От вас нужны только сами цифры: сколько продано, на какую сумму, с какой маржой.

## ABC по клиентам — отдельная секция не нужна

Для клиентского среза сайт переиспользует уже существующую секцию `clients` (её `Оборот_тек` как база для ранжирования). Если хотите, чтобы ABC по клиентам был содержательным, а не только по top-5 из примера — отдайте в `clients` полный список клиентов (в реальном отчёте вы уже упоминали 2087 клиентов; для ABC желательно передавать все, а не top-N, иначе классификация будет только по видимому срезу).
